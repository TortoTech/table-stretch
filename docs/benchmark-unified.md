# 统一端到端 benchmark

实测日期：2026-10-31（US/Pacific）。Apple M6、16 GiB 内存、macOS-27.0-arm64-arm-64bit、Rust 1.99.1，release 构建、单线程。

**8 种方法现使用统一标准重测**：同一组 64 个复杂/多样场景、同一份曲线 JSON、同一个 Rust 进程入口；每次从启动进程前到进程退出及输出收完计时。输入读取、验证、方法自身预处理、模型编译、搜索、最终拉伸与输出全部计入；每次总墙钟限时 **1 秒**。Rust 搜索次数限制在本次基准中关闭，生产库默认值不变。每场景/方法预热 1 次、测量 3 次，各方法按固定种子打乱顺序，串行运行。

场景沿用此前外部测试的选择，来自 25 本书、317 个真实表格的 2332 个宽度场景，包含此前全部 8 个 Pareto 搜索超限案例。这是复杂场景子集，不是全书库的随机抽样。

| 方法 | 完成场景 | 超时运行 | 端到端 P50（ms） | P95（ms） | PAR-2（ms） |
| --- | ---: | ---: | ---: | ---: | ---: |
| **Pareto DP（当前默认）** | 64/64 | 0/192 | 2.280 | 119.912 | 19.461 |
| A* 2011（Rust） | 64/64 | 0/192 | 2.170 | 2.497 | 2.200 |
| W3C 比例法（启发式） | 64/64 | 0/192 | 2.202 | 2.452 | — |
| 2011 CP / Gecode | 64/64 | 0/192 | 77.240 | 95.766 | 80.370 |
| 2011 CP/SAT＋LCG / Chuffed | 62/64 | 6/192 | 72.612 | 755.609 | 191.050 |
| 2015 cell-free＋LCG / Chuffed | 64/64 | 0/192 | 69.331 | 497.700 | 113.251 |
| 2015 MIP unary / HiGHS | 64/64 | 0/192 | 76.068 | 375.362 | 115.564 |
| 2015 MIP one-hot / HiGHS | 64/64 | 0/192 | 77.120 | 301.636 | 102.890 |

“完成场景”要求 3 次均在时限内完成；精确方法须证明最优，W3C 仅要求返回可行解。P50/P95 在**全部 64 个场景**上统计：先取每场景 3 次耗时的中位数，再取跨场景分位数；超时按 1000 ms 截断。PAR-2 对全部 192 次运行取平均：成功用实际耗时，超时罚为 2000 ms，越小越好；启发式不参与该精确求解评分。不能把截断耗时当作超时任务真正完成所需时间。

当前默认 Pareto 完成 **64/64** 个场景，A* 完成 **64/64**；所有已证明最优的结果均与参考最优高度一致。W3C 比例法在 34/64 个场景未达到最优高度。Rust 三种方法的端到端 P50 为 2.170–2.280 ms，其中已计入进程及输入输出成本；搜索差异另见阶段诊断。耗时表示当前实现的部署成本，不能据此推断原论文历史实现的速度。

所有方法都从预先构造的相同尺寸曲线开始，因此共同排除文本曲线构造、字体 shaping、EPUB 解压和绘制。超时保留截止时刻前收到的最佳可行布局，不标记为最优。MiniZinc 统一使用 `-O0`，相关编译器回归见[算法说明](algorithms.md#编译优化回归)。

## 超时后的可行解

所有方法在求解前运行相同的 W3C 可行布局作为兜底，成本全部计入，未把该布局作为任何搜索器的初始上界。外部求解器另外读取中间解；原生 Pareto/A* 当前没有中间解接口。以下是这个返回协议的质量，不把它当作纯搜索算法的 anytime 能力比较。相对差距为 `(返回高度−最优高度)/最优高度`。差距为零仅表示事后与参考答案一致，不表示被测求解器在截止前证明了最优。

## 可复现协议

- 输入是 `Table` 的完整阶梯曲线。清单固定源表位置、容器宽度、列上下限、曲线、参考高度和规范 JSON 的 SHA-256；每个场景的 8 种方法读取完全相同的文件字节。不是给 Rust 预先准备候选、同时给外部求解器原始文本。
- 同一 `unified_worker` 可执行文件处理全部方法。父进程在 `Popen` 前读单调时钟，收完 stdout/stderr 并等待退出后停止。参考答案校验在计时后统一进行；worker 内的解解析、校验、拉伸和序列化在计时内。临时目录和通用输入文件在计时前准备；MiniZinc 专用输入文件在计时内生成。
- 统一限制为单线程、每次 1 秒总墙钟；不再使用 Rust 的 2000 万比较限制，也不再给予外部求解器“编译完后额外 1 秒”。所有方法都不另外设置内存配额。超时杀死独立进程组，清理后才运行下一方法；清理耗时另存，不进入 PAR-2。只接受截止前完整收到的输出行，输出了最优结果但未按时退出也按超时处理。
- 外部引擎：MiniZinc 2.10.1、Gecode 6.4.0、Chuffed 0.14.0、HiGHS 1.15.1；单线程、种子 1、`-O0 --intermediate-solutions`，Chuffed 使用 `-f --vsids`。逐次新建进程，预热后测量，未清空操作系统文件缓存。方法顺序用种子 1 打乱；没有并发运行被测任务。
- 每个最优解均与参考高度比较，所有可行解独立重算原始曲线上的行高，检查列上下限、恰好填满容器、目标和可行性。参考高度来自原有 A* 全语料运行；原生算法另有全整数宽度穷举差分测试，五种外部模型此前通过 70 个独立穷举模型/实例组合（包括编译器回归）。这些检查不等于证明求解器实现对所有输入正确。
- 当前输入是从真实 EPUB 内容提取的简化词宽/CJK 字符宽模型。不支持的合并单元格未入选；不含真实字体/CSS 排版成本，不能外推为任意表格的实时保证。

```sh
# 在仓库根目录，安装 Rust 与包含 Gecode/Chuffed/HiGHS 的 MiniZinc。
python3 scripts/benchmark_unified.py --minizinc /path/to/minizinc
python3 scripts/report_unified.py
bash scripts/check.sh
```

计时脚本当前针对 macOS（环境信息使用 `sysctl`，超时使用 POSIX 进程组）。可省略 `--minizinc` 并将可执行路径写入 `.tools/minizinc-path.txt`。默认直接使用已提交的输入清单；`--rebuild-inputs` 从历史原始数据重建相同选择。测试运行可用 `--cases 1 --repeats 1 --output /tmp/smoke.jsonl`。正式报告要求完整场景集合，参数与源码/二进制哈希均存于首行元数据。

数据：[逐次记录与状态](benchmark-unified.jsonl) · [输入清单](benchmark-unified-inputs.json) · [统计汇总](benchmark-unified-summary.json) · [算法及研究范围](algorithms.md)。历史不同计时口径的结果保留在[旧报告](benchmark.md)，不混入本表。
