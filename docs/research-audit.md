# 研究实现对齐审计

审计日期：2026-10-31。审计前版本：[`11fed39`](https://github.com/TortoTech/table-stretch/tree/11fed39582c15e0dc94f5d003fb829854cfed97b)。

**旧实现不能称为论文实验的完整复现。** 相同目标、正确的最优高度，以及相同端到端计时范围，并不保证模型传播、搜索策略和原论文一致。旧版主表的方法名省略了这些差异，容易让人把适配版本的耗时当成论文方法的表现；本次已更正，并保留旧适配作为对照。

## 逐项核验

| 旧主表标注 | 实际实现与差异 | 本次处理 |
| --- | --- | --- |
| 2011 CP / Gecode | 配置索引/element 思路相符；引擎是 Gecode，且按列宽从大到小搜索。原文 §6 的 cp-w 是关闭学习的 Chuffed，按单元格最小剩余配置高度搜索。 | 重命名旧行；新增 `cp2011_chuffed_seq`。 |
| 2011 CP/SAT＋LCG / Chuffed | 有真正的 LCG，但只测了 `-f --vsids`；当前 Chuffed 的 `-f` 启用重启时切换搜索，并非原文 cp-seq，也不能标为严格固定 VSIDS。 | 重命名为混合搜索适配；新增 `lcg2011_chuffed_seq`。 |
| 2015 cell-free＋LCG / Chuffed | 相邻配置析取公式相符，但没有 RCSV 的行列取值域。 | 保留旧版；新增 `lcg2015_rcsv`。 |
| 2015 MIP unary / HiGHS | 每格一组 unary 变量，属于基础 extent 配置编码；不是共享行列变量的 cell-free MIP。 | 标明基础编码；新增 `mip2015_cellfree`。 |
| 2015 MIP one-hot / HiGHS | 每格恰选一个配置的基础 standard 编码；不能代表论文全部 MIP 改进。 | 标明基础编码，与新增 mipcf 分开报告。 |

2011 的依据是[作者上传稿 §4、§6](https://www.researchgate.net/publication/221353238_Optimal_automatic_table_layout)。2015 的依据是[作者稿](https://people.eng.unimelb.edu.au/pstuckey/papers/ijor15.pdf)搜索索引可读取的第 11、13–15、17–18 页：RCSV、cell-free、unary 与共享界文字的公式、实现说明和模型列表。2015 站点直接下载仍返回拦截页，因此这里明确区分“已核对这些段落”与“已核对整篇全文及作者源代码”；后者尚未完成。正式出版信息见 [DOI](https://doi.org/10.1287/ijoc.2014.0637)。

## 新增模型与正确性

所有模型仍优化同一个问题：整数宽度、无合并单元格、完整非增阶梯曲线、列上下限、`Σw≤B`，最小化 `Σh`，最后单调拉伸填满容器。

`cp2011_seq.mzn` 删除同高而更宽的受支配配置，使用单元格配置高度作搜索变量。`smallest, indomain_min` 每次选最小下界的未定单元格并尝试最低配置高度；同高配置删除后，格高唯一确定配置。同分顺序采用本项目列优先输入顺序。cp-w 显式关闭 lazy/learn；cp-seq 保留学习；两者都关闭 VSIDS 切换和基于冲突的重启。它们对齐已描述的搜索规则，未声称复现历史 C++ 分支器、所有同分细节或版本默认值。

还核对了 [Chuffed 0.14.0 参数解析](https://github.com/chuffed/chuffed/blob/0.14.0/chuffed/core/options.cpp)及[搜索主循环](https://github.com/chuffed/chuffed/blob/0.14.0/chuffed/core/engine.cpp)：`--no-lazy` 走不做冲突分析的回溯分支；优化时收紧目标后的回根仍会计入 `restarts`。此外，其 [`nogoods` 统计实际直接输出冲突次数](https://github.com/chuffed/chuffed/blob/0.14.0/chuffed/core/stats.cpp)，不能看到该值非零就认为无学习模式仍在学习。原始统计保留引擎字段，不把它解释成真实学习子句数量。

`lcg2015_rcsv.mzn` 在原 cell-free 上限制各行列取值集合。RCSV 是 row and column span value；无跨格时退化为单行、单列的配置值域。新增版本固定 VSIDS、不启用 free-search 切换；2015 历史搜索参数尚未全部核实。

本轮 64 个场景的 4507 条输入曲线均已压缩同高平台，符合最小配置假设。对于 API 允许的未压缩曲线，RCSV 版本可保留额外冗余候选值，保持正确但可能减弱传播；顺序搜索版本会显式去掉同高配置。

`mip2015_cellfree.mzn` 为每一行/列的有序候选值建立共享前缀二元变量。界条件直接使用对应的二元变量；一条析取变成两个界变量之和至少为 1。不再为每个单元格配置建立独立选择变量。等式重建行高/列宽；仍使用现代 HiGHS 和 MiniZinc。

本项目额外的硬列下限需要适配：候选列宽包含 `lo[j]`，不能直接照搬仅有单元格断点的集合。正确性如下：给定任一可行宽度，把每列缩至不低于硬下限的上一个断点；每格高度不变，使用宽度不增。因此保留一个最优解。每行的真实高度是该行某个单元格配置高度的最大值，属于配置高度的并集。故将行高限制到该集合也保留最优解。求解后填充余量不能增加高度；如果严格降低高度，则与求得最优矛盾。

对于有序值 `v₁<…<vₖ`，前缀二元变量 `b₂≥…≥bₖ` 和等式 `x=v₁+Σ(vᵢ−vᵢ₋₁)bᵢ` 恰好表示这些值。`x≥t` 等价于第一个满足 `vᵢ≥t` 的界变量；超出值域时是常量。因此共享 unary 的析取表达保持精确可行性。这些新增模型没有纳入 Lean 证明；由独立整数穷举和真实表格结果复核验证。

## 计时含义与剩余边界

本次还发现并修复了**超时清理缺陷**：MiniZinc 的 FlatZinc 子进程会建立自己的进程组；旧版只对 worker 的进程组发 SIGKILL，不能保证终止实际求解器。此次失败的试跑中观察到六个仍占用 CPU 的孤儿 Chuffed，已全部终止。旧报告的计时可能因此受干扰，不再作为可靠速度排名；独立校验的解质量与这项计时缺陷是两个问题。

修复后在超时时冻结仍存活的 worker 及子进程，沿父子关系递归收集并终止后代，包括另建进程组的求解器，再开始下一次测量。清理不改变 1 秒截止点，不接受清理期间收到的新解；清理耗时和 PID 列表另存。回归新增“子进程另建 session”的测试，并用真实超时的 Chuffed 检查不再留下运行进程。统一报告已从头重测，不能将修复前后的耗时混合做模型加速比。

统一的端到端比较有效：它回答“当前实现从同一曲线输入得到完整输出需要多久”。但模型转换方案也是被测实现的一部分。2011 使用 Chuffed C++ 建模；2015 MIP 使用生成线性模型的脚本和 CPLEX 12.1，且其 §6 明确排除生成线性模型的预处理时间。当前 MiniZinc 每次重新编译，不能把其额外开销解释成 CP/MIP 搜索算法固有的速度差。

本次仍使用相同 64 个固定场景、每方法预热 1 次/测量 3 次、1 秒总墙钟、串行交错、单线程/种子 1，全部转换和编译计时。旧五个外部适配保持行为不变，新四个方法加入同一轮。结果和阶段诊断见[统一报告](benchmark-unified.md)。不得从本样本推断所有规模、合并单元格或论文人工困难实例的排名。

修复后的同一轮数据（端到端 P95，全部 64 个场景；超时按 1000 ms 截断）：

| 对照 | 旧适配 P95 | 新变体 P95 | 完成场景（旧 → 新） |
| --- | ---: | ---: | ---: |
| 配置 LCG 混合搜索 → cp-seq 最小格高搜索 | 749.939 ms | 84.008 ms | 62/64 → 64/64 |
| cell-free LCG 无 RCSV → cpcf＋RCSV | 497.154 ms | 299.730 ms | 64/64 → 64/64 |
| 基础 unary MIP → mipcf 共享 unary | 374.943 ms | 154.393 ms | 64/64 → 64/64 |
| 基础 one-hot MIP → mipcf 共享 unary | 302.367 ms | 154.393 ms | 64/64 → 64/64 |

无学习 cp-w 完成 55/64，27/192 次测量超时；补齐论文策略并不保证每种方法都变快。共完成 2496 次正式测量，另有 832 次预热；所有按时完成的精确解均与参考高度一致。33 次正式超时的清理记录都包含 worker、MiniZinc、求解器三个进程；结束后未发现遗留的 worker/Chuffed 进程。全部被测源码哈希与元数据一致。

这是完整变体的对照，不是单因素消融：例如新 cpcf 同时加入 RCSV 并改用固定 VSIDS，不能把它的所有耗时变化单独归因于 RCSV。

MiniZinc `-O0` 继续保留：本次再次验证同一个 unary 回归在 `-O1` 下错误返回高度 3，而 `-O0` 和独立穷举都得到 6。不能为了改善速度启用已知错误的编译路径。具体回归见[算法说明](algorithms.md#compiler-regression)。

仍未对齐：历史求解器版本和建模接口；原始 web/artificial 数据集；合并单元格和所有 positional/glue 变体；2015 全文、完整搜索设置和作者源码。新增四项应称为**核对过关键公式/策略的简单表格适配**，而不是“完整复现”。

## 验证与复现

`python3 scripts/check_models.py`：九种外部配置 × 16 个实例 = 144 次独立全整数宽度穷举检查，覆盖随机多行多列、同高平台、零高度、不可行预算、编译器回归、硬下限位于断点之间。每次最优结果还检查原始曲线上的真实行高。正式基准逐次检查可行性及参考最优高度；超时只记录截止前已收到的解。

```sh
python3 scripts/check_models.py
python3 scripts/benchmark_unified.py --baseline-worker .tools/pareto-baseline/unified_worker
python3 scripts/report_unified.py
bash scripts/check.sh
```

优化前 worker 的可移植构建步骤见统一报告。原始数据首行包含逐模型参数、模型源码及 worker 哈希，以免修正模型后仍沿用旧耗时。
