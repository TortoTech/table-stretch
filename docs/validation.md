## 测试方法与结果

每个表格测试最小内容宽度、增加 8/24/64 单位以及完全不换行宽度，超过上限时截断并去重，共 **61 个表格/宽度组合**。

| 检查 | 结果 |
| --- | --- |
| 精确求解完成 | 61/61，无搜索超限 |
| 总列宽等于预算、每列满足上下限 | 全部通过 |
| 由返回列宽重新计算高度与返回值一致 | 全部通过 |
| 宽度增大，总高度非增 | 全部通过 |
| 与独立全整数列宽穷举比较 | 40/40 一致 |
| 不劣于“从最小宽度均摊余量”基线 | 61/61；20 个严格更矮 |
| 不劣于“按伸缩区间比例分配”基线 | 61/61；18 个严格更矮 |

穷举仅对不超过 3 列且额外宽度不超过 128 的情况运行；其余 21 例通过约束、单调性和基线检查，并依赖已证明算法的正确性，不能声称也做了独立穷举。

本次样本中相对均摊基线最大高度降幅约 31.0%，相对比例基线最大降幅约 33.3%。这是这些尺寸模型与基线的结果，**不是对 torto 现有布局器的性能或高度对比**。

`cargo run --release --example ebook_corpus` 的一次测量中，单次 `solve` 为 2～965 微秒，中位数 24 微秒；最大前沿 205 个状态，单次最多 879 次候选扩展。计时不含 EPUB 提取、JSON 解析、词曲线生成和独立穷举。此数据只是本机单次运行记录，不是稳定基准或实时性保证。完整数据见 [corpus-results.json](corpus-results.json)。

## 独立算法测试

`tests/optimality.rs` 还包含：

- 固定种子生成 240 个小型矩形表格，对每个表格从零到超过最大容量的全部整数容器宽度比较完整穷举。独立穷举不使用求解器的候选集、支配函数或二分高度查询。
- 对长度 1～6、词宽取值 1/2/3 的所有词序列，间距取 0/1/3，遍历宽度，与枚举所有最后一行断点的独立动态规划比较。
- 行高向量必要性的反例、比例分配失效反例、非法曲线、不规则表格、上下界不可行、搜索限制和大整数边界。
- CLI 标准输入/输出与失败退出约定。

`cargo test --locked`、`cargo fmt --check`、`cargo clippy --locked --all-targets -- -D warnings` 和 Lean 检查构成完整检查入口 `scripts/check.sh`。

## 度量边界

本次提取会折叠空白，把块级间隔归一为空格；英文以空白分词，词间距为 1；CJK 分支以标量字符换行。字符宽度使用 Unicode East Asian Width：W/F 为 2，组合符为 0，其余为 1。当前选中样本均为英文书中的表格。

这保留真实表格的行列结构和文本长度差异，但不保留原书字体、CSS、强制换行、连字或断字规则。要验证 torto 实际显示高度，下一步必须接入其真实文本测量器，并增加原始渲染对比；现有结果不声称完成该接入。
